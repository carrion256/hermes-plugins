# 10 hooks-compat (Claude Code / Cursor `hooks.json` adapter)
Status: proposed · Owner: — · Depends on: host seam H1 (`pre_stop` hook), H2 (public shell-hook runner); builds on `agent/shell_hooks.py`

## Goal
Drop-in compatibility with the hook files people already have: `~/.claude/settings.json`, `<repo>/.claude/settings.json(.local)`, `~/.cursor/hooks.json`, `<repo>/.cursor/hooks.json`, `$HERMES_HOME/hooks/*.json` and plugin-shipped `hooks/hooks.json`. The same scripts, written for Claude Code or Cursor, run unchanged in Hermes with the same decision contract: exit 2 denies, `hookSpecificOutput.permissionDecision` allow/deny/ask, `updatedInput`, `additionalContext`, Stop-continue capped at 8, deterministic dedup by provenance rank, and explicit trust for project-level files. Nothing runs without consent; nothing is silently reinterpreted.

## Evidence
- **Grok Build is the reference dialect** (source, Apache-2.0): Claude-shaped JSON `{"hooks":{"<Event>":[{"matcher","hooks":[{"type":"command"|"http","command","timeout"}]}]}}` plus a Cursor alias layer; 15 canonical events, `command` and `http` handlers only. `grok-build-platform.md` §3.1.1 (`event.rs:5-180`), §3.1.2 (`config.rs:93-111, 466-520`).
- **Decision contract** (source) `grok-build-platform.md` §3.1.7 (`runner/command.rs:37`, `runner/mod.rs:59-134, 357-368`): exit 2 = block (stderr is feedback); any other non-zero or a timeout = recorded failure, fail-open; valid decision JSON wins over exit code except exit 2; `permissionDecision` beats top-level `decision`; `approve`≡`allow`, `block`≡`deny`; a failed hook keeps its deny but drops `updatedInput`/`additionalContext`; PostToolUse honours only `decision:"block"` plus `additionalContext`/`updatedToolOutput`; UserPromptSubmit block reason goes to the user, never the model.
- **Stop gate** (source) `grok-build-harness.md` §6.1 (`AI/stop_gate.rs:9, 234-334`, `AI/turn.rs:1307-1396`): `Stop`/`SubagentStop`, all hooks run, blocks and `additionalContext` aggregate, feedback clipped to 10,000 chars, `continue:false` force-stops, **max 8 continuations per turn** then the gate is overridden. Table at `grok-build-harness.md:349`.
- **Provenance ranking** (source) `grok-build-platform.md` §3.1.2/3.1.5 (`loader.rs:268-280`): identity = (event, matcher, handler); first copy wins, a later byte-identical copy replaces it only with a higher `authority_rank` (SystemManaged 7 > Requirements 6 > SignedRequirements 5 > Managed 4 > UserRequirements 3 > User 2 > File/Plugin 1 > Unknown 0). Project sources need folder trust (`trust.rs:26-48`); per-hook disable file (`trust.rs:118-199`).
- **Cursor differences** (backfilled from cursor.com/docs/hooks.md, `grok-build-platform.md` §3.1.10): flat entries `{"version":1,"hooks":{"beforeShellExecution":[{"command","timeout","matcher","type"}]}}`, `permission: allow|deny|ask`, `user_message`, `agent_message`, `updated_input`, `additional_context`; permission hooks fail **closed** on invalid JSON; `type:"prompt"` exists. Grok Build itself does *not* load flat Cursor entries (inferred gap, `config.rs:94-98`), so the Cursor flat adapter is net-new here.
- **Grok Bot** (decoded): no hooks.json loader in the client; hooks run server-side as typed `ExecuteHookRequest` arms; only `hook_additional_contexts` plumbing is visible (`grok-build-platform.md:1453-1455`). No evidence to copy; Hermes supplies its own runner.

## Current state
- `agent/shell_hooks.py` already bridges `hooks:` in `config.yaml` to the plugin hook manager: stdin JSON `{hook_event_name, tool_name, tool_input, session_id, cwd, profile, extra}` (`:79-94, :391-393`), subprocess without a shell (`:297, :312`, so no `sh -c` pipes), own process group, per-hook timeout default 60 / max 300 (`:37-38`), first-use consent in `shell-hooks-allowlist.json` keyed `(event, command)` (`:478-538`), `HERMES_SAFE_MODE` skip (`:147`).
- Exit 2 blocks **only** `pre_tool_call` (`BLOCK_EXIT_CODE`, `_BLOCKING_EVENTS = {"pre_tool_call"}`, `:41-44, :365-371`); `fail_closed`/`failClosed` is honoured only there (`:270-278`).
- Output dialects: `pre_tool_call` accepts `{"action"|"decision":"block"}` and `modify` (`:402-414`); `pre_verify` accepts `{"decision":"block","reason"}` as keep-going (`:417-423`); everything else only `{"context": str}` (`:426-444`). `hookSpecificOutput`, `permissionDecision`, `updatedInput`, `additionalContext`, `ask` are **not** parsed.
- Matcher is `re.fullmatch` on Hermes tool names and only for `pre_/post_tool_call` (`:117-124, :255-258`); Claude's matcher is unanchored regex over Claude names (`Bash|Edit|Write`).
- Event vocabulary is Hermes `VALID_HOOKS` (`hermes_cli/plugins.py:110-221`) — snake_case; no `PreToolUse`/`Stop`/`UserPromptSubmit` names, no Claude/Cursor file discovery. `pre_tool_call` already supports `approve` (human-approval gate) and `modify` (`hooks.md:551-563`).
- `pre_verify` is the only stop-time gate for scripts, but fires **only when the agent edited code** and at least one hook exists, bounded by `agent.max_verify_nudges` default **3** (`agent/turn_stop_gates.py:52-76`, `agent/verify_hooks.py:16, :29-34`). Claude `Stop` fires on every text-final stop. Gap.
- Gateway `HOOK.yaml` hooks (`gateway/hooks.py:3-6, :44-53`) are a separate, in-process Python handler system for gateway/agent lifecycle events (`agent:start|step|end`, `command:*`); unrelated to command hooks, left alone.
- `UserPromptSubmit` has no blocking analogue on the CLI: `pre_llm_call` injects context only (`hooks.md:687`); `pre_gateway_dispatch` can `skip`/`rewrite` but is gateway-only (`plugins.py:155`).

## Design
**Plugin `hooks-compat`** (no CLI, no per-event reimplementation of process spawn). It owns discovery, normalisation, dedup, trust and the Claude/Cursor decision-JSON translation; it reuses the host runner for spawn/timeout/process-group/env scrubbing.

1. **Sources and provenance rank** (low→high authority is irrelevant to ordering; rank only breaks identical-hook ties, as in Grok Build):
   `hermes-managed(6)` (managed config.yaml `hooks:` — read via H2, not re-registered) > `hermes-user(5)` (`$HERMES_HOME/hooks/*.json`) > `claude-user(4)` / `cursor-user(4)` > `project(3)` (`.claude/settings*.json`, `.cursor/hooks.json`, nearest-git-root only) > `plugin(2)` > `unknown(0)`. Config keys: `sources` (list, default `[hermes, claude-user, cursor-user]`; **project sources off by default**), `compat.claude`, `compat.cursor` booleans, `disabled_hooks_file` (default `$HERMES_HOME/hooks-compat-disabled`, one canonical hook name per line, same naming as Grok Build: `{source}:{event}[g].hooks[h]`).
2. **Parse** both shapes into one internal `Spec(event, matcher, handler{type, command|url, timeout}, source, rank, identity)`. Matcher-group shape verbatim; Cursor flat entries wrapped as one-handler groups; `version` ignored; unknown events and unsupported handler types (`prompt`, `agent`, `http` in P0-P2) are **skipped with a named warning** (`skipped unsupported event 'beforeTabFileRead'`), never failing the file — but a malformed event array drops only that event (Grok Build's `SkipEvent` policy, not its whole-file `Fail`). Dedup key `(canonical_event, matcher, command)`; higher rank replaces, ties keep first.
3. **Event map** (Claude/Cursor spelling → Hermes hook, `status` of each in `hooks_compat_status`):
   | Claude / Cursor | Hermes hook | Notes |
   |---|---|---|
   | `PreToolUse`, `beforeShellExecution`, `beforeMCPExecution`, `beforeReadFile` | `pre_tool_call` | tool-class filter derived from Cursor name |
   | `PostToolUse`, `afterShellExecution`, `afterMCPExecution`, `afterFileEdit` | `post_tool_call` (+ `transform_tool_result` for `updatedToolOutput`) | |
   | `PostToolUseFailure` | `post_tool_call` when result JSON carries an error / `transform_tool_result.status` | observe only |
   | `UserPromptSubmit`, `beforeSubmitPrompt` | `pre_llm_call` (context) / `pre_gateway_dispatch` (block) | CLI cannot hard-block, see Host changes H3; until then block reason is surfaced as a warning and flagged `unenforced` |
   | `Stop`, `stop` | new `pre_stop` (H1) | |
   | `SubagentStart/Stop`, `subagentStart/Stop` | `subagent_start`/`subagent_stop` | `SubagentStop` cannot continue the child (observe) until H1 covers child loops |
   | `SessionStart/SessionEnd`, `sessionStart/End` | `on_session_start` / `on_session_finalize` | observe |
   | `PreCompact`/`PostCompact` | — (no `VALID_HOOKS` entry) | reported `unmapped`, not faked |
   | `afterAgentResponse` | `transform_llm_output` observer | Cursor semantics, not Grok's PostToolUse alias |
   | `Notification`, `PermissionDenied`, `StopFailure/Cancelled` | `pre_approval_request`/`post_approval_response`, `agent_loop_stopped`, `api_request_error` where payload fits; else `unmapped` | |
4. **Tool-name aliasing for matchers**: unanchored `re.search` against the Hermes tool name **and** its Claude aliases (`terminal`→`Bash`, `read_file`→`Read`, `write_file`→`Write`, `patch`→`Edit`/`MultiEdit`, `search_files`→`Grep`/`Glob`, `web_search`→`WebSearch`, `web_extract`→`WebFetch`, `delegate_task`→`Task`, MCP `mcp__<server>__<tool>` passes through) — same rule as `matcher.rs:1-90` (`^Bash$` must match Hermes `terminal`). Invalid regex ⇒ hook dropped at load with a warning (Grok Build installs `Never`; we drop and report). Matcher on Stop/UserPromptSubmit is warned and ignored.
5. **Payload**: stdin JSON is Claude's shape plus Hermes extras: `hook_event_name` (PascalCase), `session_id`, `cwd`, `transcript_path` (session export path if known else omitted), `tool_name` (the Claude alias when one exists; Hermes name in `hermes_tool_name`), `tool_input`, `tool_response` (PostToolUse), `tool_use_id`, `stop_hook_active` (Stop), `prompt` (UserPromptSubmit), `permission_mode`; payload capped 128 KiB with `…Truncated:true` (`event.rs:617-634`). Env: `CLAUDE_PROJECT_DIR`, `HERMES_PROJECT_DIR`, `HERMES_HOOK_EVENT`, `HERMES_HOOK_NAME`, `CLAUDE_PLUGIN_ROOT` for plugin sources. Handlers run **sequentially in rank-then-file order** (Grok Build rule).
6. **Decision translation** (`decide(event, exit_code, stdout, stderr) -> Directive`), mirroring `grok-build-platform.md` §3.1.7, with Hermes shapes as output:
   - `pre_tool_call`: exit 2 ⇒ `{"action":"block","message": stderr-first-line≤256 | permissionDecisionReason | "denied by hook '<name>'"}` (extends the host default, which already does exit 2 for this event); JSON `permissionDecision:"deny"` / `decision:"block"|"deny"` on any exit code ⇒ block; `"ask"` ⇒ `{"action":"approve","message","rule_key":"hooks-compat:<hook name>"}`; `"allow"`/`defer` ⇒ none (allow never auto-approves); `updatedInput` object ⇒ `{"action":"modify","args":…}` (non-object ignored + warned) but only if the hook did not exit non-zero; `additionalContext` ⇒ queued and appended to the same call's result via `transform_tool_result` inside a `<system-reminder>` naming the hook, dropped if the call was denied. Cursor dialect `permission`/`updated_input`/`agent_message` is honoured **only for Cursor-sourced hooks** (otherwise a document without `decision`/`hookSpecificOutput` falls through to exit-code semantics, exactly like Grok Build).
   - Cursor permission hooks: invalid JSON/schema mismatch on exit 0 ⇒ **fail closed** (deny) for `cursor-*` sources, per Cursor docs; Claude-sourced hooks stay fail-open. Honoured through the existing `fail_closed` machinery only for `pre_tool_call`.
   - `pre_stop`: exit 2 ⇒ continue with full trimmed stderr as feedback; `decision:"block"` + `reason` ⇒ continue; `additionalContext` also keeps going; `continue:false` ⇒ force-stop and wins; any hook error/timeout fail-open. All Stop hooks run; feedback joined and clipped to 10,000 chars (`MAX_HOOK_FEEDBACK_CHARS`).
   - Unknown decision token ⇒ failed hook (fail-open) unless exit 2.
7. **Stop-continue cap 8** is a plugin counter per turn (`stop_continue_max`, default **8**, hard max **8**; config can only lower it — the cap is the evidence-backed ceiling), keyed `(session_id, turn_id)` and reset by `on_session_end`. After the cap it returns no directive, sets `stop_hook_active` on later invocations, and logs an overridden-gate receipt. The host's `max_verify_nudges` (3) continues to bound `pre_verify` separately; `pre_stop` has its own gate position (after verify-on-stop, before kanban).
8. **Trust & consent** (house posture: explicit): non-project user files use the existing allowlist file, extended with `source_sha256` so editing the JSON re-prompts (`shell_hooks.allowlist_entry_for`, `:564-566`). Project files require `hooks_compat_trust <path>` (a plugin tool, not a model-callable default) recording canonical path + sha256 in `$HERMES_HOME/hooks-compat-trust.json`; a changed file is untrusted again. Non-TTY runs skip untrusted sources and list them in status — never auto-accept. `HERMES_SAFE_MODE` ⇒ plugin inert.
9. **Status tool** `hooks_compat_status` (read-only): loaded specs with source/rank/identity/event mapping, skipped items with reason, trust state, last decision per hook, Stop counter. Failures are reported verbatim; no fabricated "ok".
10. **Interaction with existing `hooks:`**: the config.yaml path is unchanged and ranks `hermes-managed`; an identical `(event, command)` from a `.claude` file is dropped as a lower-rank duplicate, so no double execution. Hooks never run through both paths.

## Host changes
- **H1 `pre_stop`** (new `VALID_HOOKS` entry; fire in `agent/turn_stop_gates.py::apply_stop_gates` between pre_verify and kanban, `:141-151`). Signature `pre_stop(session_id, platform, model, turn_id, final_response, attempt, changed_paths, edited: bool) -> {"action":"continue","message"} | {"action":"stop"} | None`; reuses `_continue()`, counter `agent._pre_stop_nudges`, `finish_reason="stop_hook_continue"`. Why not `pre_verify`: it is gated on `_edited and has_hook("pre_verify")` (`:61`) and the documented contract "once per turn when the agent edited code" (`hooks.md:810-812`); widening it would change every existing consumer (continuation, loop-guard).
- **H2 public runner**: promote `shell_hooks._spawn` + `ShellHookSpec`-free call into `run_hook_command(command, stdin_json, *, timeout, env_extra, cwd) -> {returncode, stdout, stderr, timed_out, error}` (the body of `_spawn`, `:288-331`) and add shell-string support (`sh -c` when the command has shell metacharacters, matching `command.rs:141-148`; Claude scripts routinely use `$CLAUDE_PROJECT_DIR/.claude/hooks/x.sh --flag | jq`). Interim until merged: plugin imports the private `_spawn` guarded by a signature check and reports `host_seam: private-runner`.
- **H3 `pre_user_prompt` block (optional, P3)**: allow `pre_llm_call` (or a new directive) to return `{"action":"block","message"}` on CLI; gateway already has `pre_gateway_dispatch`. Without it `UserPromptSubmit` block is reported `unenforced`.

## Phases
- **P0 – parser + status, nothing executes.** Acceptance: given a fixture Claude `settings.json`, a Cursor flat `hooks.json` and a plugin `hooks/hooks.json`, `hooks_compat_status` lists correct events, aliases, ranks, dedup of a byte-identical pair (higher rank wins), and named skip reasons for `beforeTabFileRead`, `type:"prompt"`, and an invalid matcher regex; a malformed `Stop` array drops only `Stop`.
- **P1 – PreToolUse/PostToolUse parity (no host change beyond H2 interim).** Acceptance (loopback model, real loader): exit-2 script denies a `terminal` call with its stderr as the tool error; `permissionDecision:"ask"` opens the native approval gate and a deny/timeout blocks; `updatedInput` rewrites the executed args and the modified args are what the approval key scopes; `additionalContext` appears once in the result as a reminder naming the hook and is dropped when the call was denied; exit 1 / timeout / non-JSON stdout = call proceeds, warning recorded; `^Bash$` matcher fires for `terminal`.
- **P2 – Stop gate (needs H1).** Acceptance: a Stop hook that always exits 2 produces exactly 8 continuations in one turn then the turn ends with `Completion`-style receipt "stop gate overridden at 8"; `continue:false` ends immediately; `stop_hook_active` is true from the 2nd invocation; verify-on-stop and kanban gates still run first/after unchanged.
- **P3 – session/prompt/subagent observers + trust UX.** Acceptance: project-level file is inert until `hooks_compat_trust`, re-inert after a byte change; non-TTY never prompts; `UserPromptSubmit` is `enforced` on gateway (`pre_gateway_dispatch` skip) and `unenforced` on CLI until H3.
- **P4 (optional) – `http` handler.** https-only, no redirects, SSRF block list (`grok-build-platform.md` §3.1.8), no custom headers; same decision mapping. Ship only on request.

## Tests
`tests/test_hooks_compat_parse.py` (fixtures for Claude/Cursor/plugin files; rank/dedup; skip reasons), `tests/test_hooks_compat_decisions.py` (table-driven `decide()`: every row of §3.1.7 incl. "JSON deny wins on any exit", "allow + exit 2 ⇒ deny", "failed hook drops updatedInput/additionalContext", Cursor fail-closed vs Claude fail-open), `tests/test_hooks_compat_runtime.py` (real `PluginManager` + real subprocess scripts, `pre_tool_call` deny/approve/modify and Stop cap via the loopback model used by the existing continuation tests). Stop-cap test asserts the 9th stop is *allowed*, not that 8 happened by accident.

## Risks & open questions
- Tool-input shapes differ (Claude `Bash.command` vs Hermes `terminal.command`; `Edit.file_path/old_string/new_string` vs Hermes `patch`): scripts that inspect `tool_input` may misread. Mitigation: alias only names in P1; add a per-tool input translator table as inferred, labelled, test-covered; unknown tools pass Hermes shape unchanged and status says so.
- Grok Build's own claim that Cursor files "load unchanged" is contradicted by its parser (`config.rs:94-98`, §3.1.10 / open question at `grok-build-platform.md:1474`); our flat adapter is therefore unverified against a real Cursor file — needs a probe before P0 is called qualified.
- `sh -c` support widens the command surface; consent is per `(event, command, source_sha256)`, and project files stay off by default.
- Two hooks both attached to `pre_tool_call`: Hermes already selects block > approve > modify across callbacks (`hooks.md:559`); Claude's "first deny short-circuits, remaining hooks don't run" differs (we run all, then host picks). Accept; document.
- Cursor's `type:"prompt"` hooks need an LLM call; out of scope.
- The 128 KiB stdin payload cap is Grok Build's (`event.rs:617-634`); Hermes' `shell_hooks.py` stdin path has no verified cap (`:391-393`), so P0 must measure before copying the number.

## Non-goals
Reimplementing hook processes or a second allowlist; replacing `config.yaml hooks:` or gateway `HOOK.yaml`; managed/signed policy tiers beyond the rank numbers; marketplace/plugin install flows; `PreCompact`/`PostCompact` emulation; async/parallel hook execution.
