# 16 memory-v2 (memory provider plugin)
Status: proposed · Owner: — · Depends on: none (no host seams). Soft: `17-mock-harness` (loopback model for the acceptance tests). Plan 15 is not present in `docs/plans/` and nothing here depends on it.

## Goal
Give Hermes a Grok Build–style typed memory: every capturable turn yields small typed observations in an inbox; a gated "Dream" pass consolidates them into a handful of curated topic notes; a bounded index (≤8 KiB / ≤64 entries) of those notes is injected once per session; the model reads topics on demand and must verify before relying on them. Ships as one external memory provider, `plugins/memory-v2/`, activated with `memory.provider: memory-v2`. Dream is **shadow-first**: it writes a validated plan and diff; applying it is explicit. Builtin `MEMORY.md`/`USER.md`, `session_search` and the holographic store are never mutated; existing content is imported read-only.

## Evidence
- **Grok Build v2 pipeline [source]** (`re/docs/grok-build-harness.md` §6.2, lines 788-799): capture → inbox → Dream → topics, no vector search. `/remember` writes an immutable manual observation; size cap `MAX_MANUAL_OBSERVATION_BYTES` (`artifacts/grok-build/crates/codegen/xai-grok-memory/src/v2.rs:18-31`, with `MAX_SOURCE_BYTES` 64 KiB and `MAX_MANIFEST_ENTRIES` 512 in the same block).
- **Capture [source]**: no-tool extraction call with a JSON schema; type ∈ `user|feedback|project|reference`; statement ≤1024 B, `topic_hint` ≤128 B, body ≤8 KiB, keywords/aliases ≤16 each ≤64 B, ≤128 observations (`shell memory/v2_capture.rs:199-224`). Request: `max_output_tokens=16384`, `reasoning_effort=Low`, no tools, 120 s timeout, 5 min lease, ≤3 attempts; transcript budget 512 KiB / 512 items, halved per attempt to a 64 KiB / 64 floor (`memory_capture.rs:330-347`). Prompt version `memory-v2-capture-1` (`shell memory/v2_capture.rs:14`). Capturable turn = real human prompt, not slash/bash/synthetic, ended by `EndTurn` (`re/docs/grok-build-harness.md:795-797`). Capture prompt (`re/data/prompts/grok-build/agents-memory-v2-capture-prompt.md:15-17,20`) treats a cancelled turn as "unfinished work, never a result" and excludes task state, tentative conclusions, secrets and repo-covered content.
- **Dream [source]**: eligible at ≥20 pending observations (`V2_DREAM_MIN_PENDING_COUNT`) or oldest ≥24 h (`V2_DREAM_MAX_PENDING_AGE`), constants at `xai-grok-shell/src/session/acp_session_impl/v2_memory_dream.rs:1-12`, used at `:605`; shadow rollout branch at `:592` and `:608`. Request: user message JSON `{operation_id, claimed_observations, existing_topics}`, claimed ≤512 observations (each ≤16 KiB), existing topics ≤128 (≤2 MiB total), tools `[]`, JSON schema `dream_plan_schema()`, 30 min total / 15 min idle timeout (`v2_memory_dream.rs:5-10,110-159,918-923`). Plan limits: ≤128 operations (`MAX_TOPIC_OPERATIONS`, enforced at `xai-grok-memory/src/v2_consolidation.rs:948-950`, constant at `:28`); topic ≤256 KiB and path ≤240 B (`v2_consolidation.rs:25-29`). Provenance comments are stripped and the model must not mention tools, MEMORY.md, databases or other Dreams (`re/data/prompts/grok-build/agents-memory-v2-dream-prompt.md:2,4-8`).
- **Conflict**: `re/docs/lineage-backfill.md:349` says "24 h + 5 sessions". The source has no session count; source constants win and the 5-session trigger is treated as unsupported.
- **Index injection [source]**: `<memory-context>` per-scope manifests, default 8 KiB / 64 entries, description ≤512 B; compact variant titles-only, ≤512 entries (`v2.rs:91-140`). Persisted in the leading system message and reused verbatim on resume (`re/data/prompts/grok-build/agents-memory-recall-injection.md:3-30`). `<memory>` guidance says memory is "historical context, not current truth" and forbids secrets (`agents-memory-v2-system-prompt-block.md:21-23`).
- **Grok Bot [decoded/inferred]**: tool `RecallMemory` (`re/docs/tools-and-prompts.md:218`; tool list `re/docs/coordinator-and-box.md:426`); RPC names `ListGrokBotUserBotMemories`, `PromoteGrokBotMemoriesToTeam{agent_id,fact_ids[]}`, `GetGrokBotTeamContextSummary` (`re/docs/coordinator-and-box.md:447`); onboarding "sorting" UI (`re/docs/electron-main-addendum.md:294`). Bot extractor/consolidator prompts are **[unknown]** (`re/docs/lineage-backfill.md:600`).
- **droid [observed]**: only AGENTS.md, skills and commands reach the request (`/var/lib/hermes/projects/droid/notes/DEEP-FINDINGS.md:178`). No droid memory-store evidence was found; the earlier "2.1.17 memory removal" row belongs to Cursor's column and is not cited here.

## Design
**Shape: provider plugin, zero host changes.** `plugins/memory-v2/{plugin.yaml,__init__.py,cli.py,store.py,capture.py,dream.py,index.py,migrate.py}`; installed by linking into `$HERMES_HOME/plugins/memory-v2/`, then `memory.provider: memory-v2`. `__init__.py` defines `MemoryV2Provider(MemoryProvider)`; `plugin.yaml` has `manifest_version: 2`, `api_version: 1`, `provides_tools` (below), `config_schema` (below). Selecting it displaces any other external provider; builtin MEMORY.md/USER.md keeps working.

**Store** `$HERMES_HOME/memory-v2/`, scopes `global/` and `workspaces/<id>/` (id = hash of git common-dir / remote origin, falling back to `agent_workspace`; clones and worktrees share it). Per scope: `topics/<slug>.md`, `observations/_inbox/*.md`, `observations/_archive/`, generated `MEMORY.md`, `dreams/<id>/{plan.json,diff.md,before/,status}`; per root `state.db` (SQLite: `capture_jobs`, `observations`, `dream_runs`, `tombstones`). Files are authoritative; `state.db` is a rebuildable index except tombstones and dream journals. Observation file = frontmatter (`type, topic_hint, statement, keywords[], aliases[], session_id, turns, prompt_version, source, content_hash, captured_at`) + body. All writes: temp file + atomic rename under a per-scope `fcntl` lock; claims use a lease row so gateway and cron processes never double-claim.

**Capture** (`sync_turn`, already off the reply path). Skip unless `agent_context == "primary"`, the user text is a real human prompt (not slash/bash/synthetic, not `TRIVIAL_PROMPT_RE`, not from a bot author: `turn_context.py:777` derives `author_is_bot` from `turn_author.get("is_bot")`) and capture is enabled. Interrupted turns are not synced by Hermes (`run_agent.py:888`), so they capture nothing; this deliberately differs from Grok Build, which keeps cancelled turns as unfinished work. Build the condensed transcript from `messages` (reasoning dropped, tool output and arguments truncated, truncation markers declared in the prompt). Call `call_llm(task="memory_v2", …)` with the Grok Build capture prompt, adapted verbatim except type semantics. Validate the reply locally with a strict schema (unknown fields rejected, caps above), then run `tools.memory_tool_store._scan_memory_content` (`:26`) over every statement and body and **drop** any observation that matches. Validation is ours; no JSON-mode dependence. ≤3 attempts with a halved budget; failure is recorded in `capture_jobs` (`failed`, reason) and writes nothing. `outcome: noop` is the common clean path and costs one call. `on_memory_write` mirrors builtin writes into the inbox (`user → type user`, `memory → project`, `source: builtin-mirror`, idempotent on content hash). `on_pre_compress` returns this session's pending observations so the summary keeps them, and flushes the capture queue.

**Dream** (`dream.py`). Eligibility is checked after each capture, at `on_session_end`, and by `hermes memory memory-v2 dream`: pending ≥ `dream.min_pending` (20) or oldest ≥ `dream.max_age_hours` (24). Claim ≤512 observations plus current topics, one call with the Grok Build Dream prompt and schema, 30 min / 15 min timeouts, `agent_context` primary or CLI only. The plan is validated whole or rejected whole: every operation cites exact claimed paths, topic paths match `^topics/[a-z0-9-]+\.md$`, sizes are within the Grok caps above, no operation touches a path outside the claim, and rename/merge/split sources must exist. `dream.mode`:
- `shadow` (default): persist `plan.json` and rendered `diff.md`, status `proposed`, claimed observations released back to pending. Nothing visible changes. `memory_v2_status` lists proposals; `hermes memory memory-v2 dream show|apply|reject <id>` is the review step (per-operation accept; team promotion is a separate explicit choice).
- `apply`: opt-in by config; applies immediately with the same validator.

Apply = copy pre-images to `dreams/<id>/before/`, write topics atomically, move claimed observations to `_archive/`, regenerate `MEMORY.md`, mark `applied`; `dream rollback <id>` restores pre-images. Provenance comments are added by the host and never trusted from model output.

**Index + injection** (`index.py`, `system_prompt_block`). Deterministic generator: title (first `# ` line) + one-sentence description (≤512 B) per topic, ordered by use then recency, then pending-observation statements, capped at `index.max_bytes` (8192) and `index.max_entries` (64). `index.compact: true` = titles only, ≤512 entries. The `<memory>` guidance block (adapted from the Grok Build block: tool names, verify before relying, secrets prohibition) and `<memory-context>` manifests are computed once at `initialize` and persisted to `state/index_snapshots/<session_id>.md`; `on_session_switch` rebinds so resume and compression replay the same bytes. Mid-session writes never change the prompt.

**Recall.** Primary path is the index plus tools (Grok Build v2 has no per-turn search). Tools use a `memory_v2_` prefix, so they do not share the bare `memory` name: `memory_v2_search` (SQLite FTS5 over topics and observations; lexical only, BM25, scope filter), `memory_v2_read` (path under a scope; returns file and mtime), `memory_v2_remember` (explicit user-requested note → immutable inbox observation ≤64 KiB, same scan), `memory_v2_forget` (tombstone; only `topics/` and `observations/`), `memory_v2_status` (counts, pending age, proposals, last capture/dream failures, budget use, overlap warnings), `memory_v2_promote` (team, below). Design choice: the model never edits `topics/` through file tools; writes stay behind these tools. Optional `recall.prefetch: off|first_turn|every_turn` (default `off`) emits a `<memory-context>` hit block (snippet ≤500 chars, staleness notes by observation age) through `prefetch`/`queue_prefetch`; `recall_status()` feeds `describe_recall`. Scores are never fabricated; empty results inject nothing.

**Team promotion.** Optional third scope `team_dir` (a shared path or git checkout). `memory_v2_promote(paths[])` copies topics (never raw observations) to `team/topics/` only after explicit consent naming the exact paths, re-running the secret scan; the team manifest is injected read-only as a third manifest. No automatic promotion, no sync daemon. Maps to Grok Bot `PromoteGrokBotMemoriesToTeam` and `GetGrokBotTeamContextSummary` (summary = `memory_v2_status`).

**Config** (provider `config_schema`): `capture.enabled: true`, `capture.timeout_s: 120`, `capture.max_attempts: 3`, `dream.mode: shadow`, `dream.min_pending: 20`, `dream.max_age_hours: 24`, `dream.timeout_s: 1800`, `index.max_bytes: 8192`, `index.max_entries: 64`, `index.compact: false`, `recall.prefetch: off`, `inbox.max_pending: 2000` (capture pauses and `status` warns when hit), `archive.retention_days: 30`, `team_dir: ""`. Model pin via `auxiliary.memory_v2` (low reasoning effort where supported). Selecting the provider is consent to send transcripts to that auxiliary model; setup text says so and recommends a local pin.

**Overlap with core.** With memory-v2 active, background review (`memory.nudge_interval`, `config_defaults.py:1221`) could also write memory and double-capture. The plugin does **not** change config; `memory_v2_status` reports the overlap and the one-line command to disable it.

**Failure modes.** Aux model down or timeout → job `failed`, retried next trigger, no partial write. Invalid reply → dropped and counted. Dream plan invalid → rejected whole, observations stay pending. Crash mid-apply → journal in `dreams/<id>` lets `recover` finish or roll back on next init. Stale lease → expires after 5 min. Missing `hermes_home` or unwritable store → `is_available()` false with `unavailable_reason()`.

## Host changes
None. Everything uses existing provider hooks, `call_llm`, the `plugins/memory` discovery and `kind: exclusive` detection. Interrupted-turn skipping is already native (`run_agent.py:888`), so no seam is needed. P1 verifies the `messages` shape the transcript builder receives before relying on it.

## Phases
- **P0 store + index (no model).** Observation and topic file formats, atomic locked writes, `state.db`, index generator with budgets, snapshot per session, `memory_v2_read/search/remember/forget/status`. Accept: loopback agent session shows one `<memory>` + `<memory-context>` block in the system prompt, ≤8192 B and ≤64 entries for a 200-topic fixture; adding a topic mid-session leaves prompt bytes unchanged; resume reproduces identical bytes; `forget` tombstone blocks recreation; `remember` of a secret-looking string is refused.
- **P1 capture.** `sync_turn` extraction, validator, scan, retries, `on_memory_write` mirror, `on_pre_compress`. Accept: a loopback model returning `noop` writes nothing; a valid reply writes files named `<session>__t…__n000.md` with correct frontmatter; malformed, over-cap or unknown-field replies write nothing and appear as `failed` in status; subagent, cron and flush contexts capture nothing; an interrupted turn captures nothing.
- **P2 Dream shadow.** Eligibility, claim, plan validation, `plan.json`/`diff.md`, `dream show/reject`. Accept: 19 fresh notes → not eligible; 20 → eligible; 1 note aged 25 h → eligible; invalid plans (bad path, evidence outside claim, >128 operations) rejected whole; nothing under `topics/` changes in shadow mode; concurrent processes claim disjoint sets.
- **P3 apply + rollback + migration.** `dream apply/rollback/recover` and importers (below). Accept: apply moves exactly the claimed files to `_archive/`, regenerates `MEMORY.md`, and rollback restores byte-identical pre-images; crash injection between steps recovers on next init; import is idempotent (second run adds 0).
- **P4 team + prefetch + evaluation.** `memory_v2_promote`, `recall.prefetch`, evaluation harness. Accept: promotion without consent writes nothing; prefetch off by default injects nothing; evaluation report produced from a loopback run and, separately, a labelled live run.

**Migration** (`migrate.py`, `hermes memory memory-v2 import`; read-only on sources, writes inbox observations with `source: import:<store>`, idempotent by content hash, dry-run by default):
- builtin `MEMORY.md` → `project`, `USER.md` → `user`, split on `"\n§\n"`; originals untouched, still the builtin store.
- holographic `memory_store.db` facts (category `user_pref → user`, `project → project`, else `reference`; categories per `holographic/__init__.py:55-74`) opened `mode=ro`; schema verified in P3 before writing the reader.
- Imported items consolidate through the normal Dream and count toward the ≥20 trigger. Rollback = `memory.provider: ""` (or the previous provider); `memory-v2/` is left on disk. Other providers (hindsight, mem0, honcho) are not imported.

## Tests
`tests/test_memory_v2.py`, using the native `plugins/memory` loader, a disposable `HERMES_HOME`, and a loopback model for `call_llm` (from plan 17):
- provider discovered as `exclusive`, selected via `memory.provider`, tool schemas non-colliding with core names, `is_available` behaviour.
- index budget, determinism and snapshot tests (P0); capture validator and scan matrix (P1); eligibility boundary table at 19/20 notes and 23 h/24 h (P2); plan-validator rejection table; apply/rollback byte-identity and crash injection (P3); import idempotency (P3); two-process claim race with `multiprocessing` (P2).
- `tests/test_memory_v2_session.py`: real CLI session through the loopback model, proving capture → inbox, Dream shadow plan, `apply`, and that the next session's system prompt contains the new topic title and a `memory_v2_read` call returns it.

`evaluation/memory_v2/` (offline, no network): ~40 fixture transcripts with gold observations and no-fact controls, secret-bearing transcripts, stale-vs-new contradictions; scripts `evaluate_capture.py`, `evaluate_dream.py`. Metrics: gold-fact recall, false-capture rate on no-fact transcripts, secret leakage (must be 0), plan validity rate, fact preservation and stale-fact removal after Dream, index budget adherence, and with/without-memory task success. Live-model results are reported separately as retrospective, never mixed into loopback pass/fail.

## Risks & open questions
- The shape of `messages` for a completed turn (tool-call and tool-output encoding) is not yet verified against `run_agent.py`; P1 reads it before the transcript builder is written.
- Transcript egress: every capturable turn is sent to the auxiliary model. Mitigation is documentation, the model pin, and `capture.enabled`; default is on because selecting the provider is the opt-in. Revisit if reviewers disagree.
- One-external-provider rule means memory-v2 replaces holographic or hindsight rather than layering; mirrored `on_memory_write` and import soften this.
- FTS5 availability depends on the Python sqlite build; fallback is a plain grep scan with a `status` flag, not silent degradation.
- Capture quality on non-coding chats is unknown (Grok Bot's own extraction prompts are unknown, `lineage-backfill.md:600`); type semantics `user|feedback|project|reference` may need tuning from the evaluation.
- Dream cost: one large call per trigger; `dream.max_age_hours` bounds idle spend; shadow mode bounds blast radius.
- Workspace id for non-git directories falls back to `agent_workspace`; gateway sessions without a workspace write to `global/` only.
- The 24 h + 5-session trigger in `lineage-backfill.md:349` is unsupported by source and is not used.

## Non-goals
- Vector or embedding search (Grok Build v2 has none; legacy hybrid search not ported).
- Replacing builtin `MEMORY.md`/`USER.md`, `session_search`, skill curator (`agent/curator.py`) or background review.
- Letting the model edit topics via file tools; batch Dream (`re/data/prompts/grok-build/agents-memory-v2-batch-dream-prompt.md`); Grok Bot server-side memory sync.
- Auto-promotion to team, cross-profile sharing, or importing hindsight/mem0/honcho stores.
- Treating memory as instructions or authorization: notes are historical context to verify, never rules.
