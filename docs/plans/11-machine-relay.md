# 11 machine-relay (`hermes-machine` plugin + daemon)
Status: proposed · Owner: — · Depends on: 02 (approval/policy engine: `always|ask|never` semantics), 12 (computer-use guard, only for the P4 `local_tool` frame). No host seam required.

## Goal
Let a Hermes agent act on the user's own computer (laptop/desktop behind NAT) with no inbound port, sshd or VPN on that machine: a small `hermes-machine` daemon on the computer dials **out** to the Hermes host, announces what it can do, and executes approval-gated requests (shell, read, ls, upload, download, later computer-use). The agent addresses a machine only by explicit `machine_id` (`list_machines` discovers them); Hermes' own host stays the default "box". Modelled on Grok Bot's user-computer plane; no hosted relay service is needed because the Hermes host is already reachable by the user.

## Evidence
- **Plane B transport** (decoded): identity = `machine_id` + server-minted `credential` carried in each request body (agent-protocol.md §3.1). Three calls: `Watch` server-stream (doorbell: `connected{pending_request_count} | notify | heartbeat{pending_request_count}`), `Poll{ack_ids[], limit=64}` → `requests[{id, frame, enqueued_at_ms}]` (ids acked on the *next* poll, daemon dedupes by id), `Submit{frames[]}` → `{accepted_count}` (agent-protocol.md §3.2; local-exec-daemon.md §2.2). Requests are NOT in the watch stream; the daemon needs no inbound port and "survives NAT" (coordinator-and-box.md:477, §4 list item 3).
- **Frames** server→daemon: `exec`, `upload` (≤100 MiB = 104 857 600), `download` (4 MiB `file{data,seq,last}` chunks), `retire_approval`, `cancel`, `local_tool`, `discover_ai_tool`, (`messages_op` macOS-only, dropped here) (agent-protocol.md §3.3; local-exec-daemon.md §3.1-3.6). Responses: `client`, `control` (`heartbeat`, `streamClose`, `throw` + `cwd_state`), `file`, `file_error`, `local_tool_*`. Batching ≤8 MiB or ≤256 frames; submit retry 3×200 ms then drop (agent-protocol.md §3.4).
- **Limits** (decoded, daemon consts): per-running-exec control `heartbeat` every **3000 ms**; ≤**8** in flight, **64** backlog, overflow error *"The user's computer is busy with other requests right now; try again shortly."*; poll limit 64; reconnect backoff 1→60 s ×2; watch stall 35 s, silence 15 s, safety poll 30 s; data deadline 120 s, control 10 s (local-exec-daemon.md §2.2 constants; agent-protocol.md §3.5).
- **Handlers**: exactly four real executors — `shellStream`, `backgroundShellSpawn`, `read`, `ls` (local-exec-daemon.md §0.1, §4.1-4.4). `hello` = `{label, local_root, terminals_folder, standing, supervised, variant, capabilities{…}}`, rebuilt/re-sent when inputs change (agent-protocol.md §3.2).
- **Routing** (decoded strings): "Local vs box is a machineId switch"; the default computer is the box; Shell/Read/AwaitShell/CopyToBox/CopyFromBox/Computer/Screenshot run on the desktop only with `machineId`; >1 registered machine without it errors *"More than one user machine is registered. Call ListMachines and retry with machineId…"* (coordinator-and-box.md §0.4 line 15, line 391; tools-and-prompts.md §4.2 transport family, line 144).
- **Approval/gate** (decoded): action classes `run-command, send-input, read-file, list-directory, write-file, read-ai-tool-setup` global; `use-app` subject; frame flags `authorized_by_approval|standing`; approvals matched on `{machine, action, target}` (or `resourcePath`), retired via `retire_approval`; user settings `always|ask|never` with ceiling `min` (local-exec-daemon.md §5.2; tools-and-prompts.md §7.4). Refusal texts are model-steering ("Do not retry…", who to ask).
- **Path containment** (decoded): read/ls/upload/download go through `X8` (root-relative check + realpath symlink check); **shell is not jailed** (local-exec-daemon.md §4.5). Recommended minimum daemon in §9 (inferred).
- **droid comparison** (source/observed, droid notes): the droid daemon dials `relayAgentUrl`, the *client* dials `relayClientUrl` (`wss://relay.factory.ai`) — a hosted relay joins two outbound sockets; versioned WS subprotocol, auth frame (API key/JWT + org), reply `relay.auth_ok`/`relay.auth_error` with codes `computer_already_connected` (bounded retry), `unauthorized`, `service_unavailable`, `rate_limited`, `wrong_region` and dispositions retry/terminal/bounded_retry; limits stale 5 s, reconnect grace 15 s, 256 KiB/512-frame buffer (DEEP-FINDINGS.md:224-227; notes/arch/server-cloud-and-decision.md:162-180). Relay token mint/`wrong_region` routing is server-side and unknown.

## Current state
- Hermes terminal backends are **host→target, session-scoped**: `TERMINAL_ENV` selects local/docker/ssh/… per session scope (`tools/terminal_tool.py:4-6`, `:389`); `SSHEnvironment` spawns `ssh … bash -c` from Hermes to a reachable sshd, reusing one ControlMaster per SendEnv set (`tools/environments/ssh.py:48-50` docstring, `:88-92`, `:115-116`). One backend at a time, inbound to the target.
- No machine registry, no `machine_id` routing, no outbound-dialing executor: grep for `machine_id|list_machines` under `tools/` finds nothing.
- Plugin API already covers everything needed: `register_tool` (`hermes_cli/plugins.py:483`), `register_cli_command` (`:684`), `register_hook` (`:939`), `on_unload` (`:436`), `register_redaction_patterns` (`:925`), and `pre_tool_call` `{"action":"approve","rule_key","revalidate"}` routed through the host approval gate: `hermes_cli/plugins.py:2044-2061` calls `tools/approval.py:1001` `request_tool_approval`.
- Gap: nothing lets the agent run a command on a NAT'd machine it cannot dial, nor address several machines per call.

## Design
**Decision:** plugin `plugins/machine-relay/` (server side) + separate stdlib-only package `daemon/hermes-machine/` (user computer). Per-call tools, **not** a terminal backend and **not** overrides of built-in tools: backends are session-scoped and inbound; overriding `terminal`/`read_file` schemas breaks prompt-cache parity and silently reroutes. No hosted relay: the Hermes host *is* the rendezvous (droid needs a relay only because both its endpoints are user-side). Wire frames stay transport-agnostic so a wss relay mode can be added (P5) without touching handlers.

**Server plugin**
- State: `$HERMES_HOME/machine/relay.db` (SQLite WAL, authoritative). Tables: `machines(machine_id, label, cred_sha256, created_ms, expires_ms, revoked_ms, hello_json, last_seen_ms)`, `queue(seq, machine_id, request_id, frame_json, enqueued_ms, expires_ms, state[queued|delivered|acked|done|expired])`, `responses(request_id, idx, frame_json)`, `approvals(approval_id, machine_id, action, target, resource_path, retired_ms)`.
- `hermes machine serve` (via `register_cli_command`): stdlib `ThreadingHTTPServer`, the only long-lived process; run it as a systemd/service unit next to the gateway. Tools in *any* Hermes process enqueue rows and wait on `responses` by polling the DB (≤100 ms); the server rings Watch streams by scanning for new rows every 250 ms. `# ponytail: DB-poll doorbell; ceiling ~dozens of machines — upgrade to a unix-socket notify.`
- HTTP (JSON): `POST /machine/v1/watch` (body `{machine_id, hello}` → SSE events `connected|notify|heartbeat` each with `pending_request_count`, heartbeat every 5 s (Hermes choice: Grok's Watch heartbeat interval is not decoded; only the 3 s exec-stream heartbeat is)), `POST /machine/v1/poll {machine_id, ack_ids[], limit≤64}`, `POST /machine/v1/submit {machine_id, frames[]}`. Credential in `Authorization: Bearer hm_<43 chars>` (header, not body — deliberate deviation: avoids body-logging leaks); `machine_id` still in body and must equal the credential's bound id). Second live Watch for a machine: newer wins only if the old stream was silent >15 s, else `machine_already_connected` (retry-bounded, droid taxonomy).
- Error vocabulary (daemon acts on `code`): `unauthorized`/`removed` (terminal: drop credential, stop), `machine_already_connected` (bounded retry), `rate_limited` and `service_unavailable` (retry with backoff), `machine_mismatch` returned as plain `unauthorized` (no oracle).
- Tools (`toolset: machine`): `list_machines` (label, machine_id, online = `last_seen` ≤ 20 s, `local_root`, capabilities, permission), `machine_shell {machine_id, command, cwd?, timeout_ms?, background?}`, `machine_read {machine_id, path, offset?, limit?}` (also polls background logs `<root>/terminals/<id>.txt`), `machine_ls {machine_id, path}`, `machine_copy {machine_id, direction: to_machine|from_machine, hermes_path, machine_path}`. `machine_id` is required; with `default_machine` unset and 1 machine it is still required (explicit > implicit); 0 machines → error naming `hermes machine enroll`; >1 and missing → Grok's string "More than one user machine is registered. Call ListMachines and retry with machineId so the action is not sent to the wrong machine." (coordinator-and-box.md:391), adapted to this plan's `list_machines` / `machine_id` names. Offline machine → "machine disconnected" immediately (no queue) unless `queue_when_offline: true`; queued requests expire after `request_ttl_s` (60) with "The user's computer stopped serving requests before this one started. Retry it once the computer is back." Cancel after start returns "cancelled — the action may have run".
- Approvals (plan 02): `pre_tool_call` on `machine_*` returns `{"action":"approve","rule_key":"machine:<id>:<run-command|read-file|list-directory|write-file>","revalidate": fn}` so the host gate (once/session/always, gateway pending, fail-closed with nobody to ask) owns the decision; `revalidate(final_args)` rechecks machine still enrolled+online and normalised path. The tool handler mints an `approval_id` from `post_tool_directive` (`approval_gate=="approved"`, `plugins.py:112-124`) keyed by canonical `(machine_id, action, target)` hash and sends it with `authorized_by_approval:true`; `retire_approval` frames follow session end (`on_session_finalize`). `approval: ask|always|never` (default `ask`; `never` refuses before enqueue with the §5.2 "Local tools are turned off…" wording).
- Credential: `hermes machine enroll --label L` mints `machine_id` (uuid4) + `hm_…` secret, stores only `sha256`, prints a one-time enrollment URL; `revoke` sets `revoked_ms` (next call → `removed`). Default expiry 90 d. Constant-time compare. Redaction pattern `hm_[A-Za-z0-9_-]{20,}` registered via `register_redaction_patterns`. Non-loopback bind requires `allow_non_loopback: true` and TLS terminated by the operator's proxy (Caddy/NetBird); daemon refuses `http://` to non-loopback unless `--insecure-transport`.

**Daemon (`hermes-machine`)**
- `enroll <url>` writes `~/.config/hermes-machine/credential.json` (dir 0700, file 0600; refuses wider modes — a Hermes choice, Inferred from Grok's support-dir credential handling). `run` loop = Grok's provider state machine: Watch(hello) → on `connected` Poll+flush, safety poll 30 s (`agent-protocol.md:158`), `Unauthenticated` ⇒ requeue + drop credential. Timers copied from Grok's Watch channel (`agent-protocol.md:161-162`, `local-exec-daemon.md:160`): stall 35 s, silence 15 s (renew on a new connection), reconnect 1 s→60 s with full jitter, silent renewal 2 s→60 s. The exec channel's 1 s→10 s ×2 backoff is at `local-exec-daemon.md:522`; the Watch channel's growth factor is not decoded, so this plan uses ×2 as a Hermes choice.
- Dispatch pipeline per poll: dedupe by queued id → push to `pending_acks` (acked next poll) → cancel handled inline → request-class frames: ≤8 in flight else backlog ≤64 else the "busy" error. In-flight de-dup by `request_id`.
- Handlers: `shell_stream` (`bash -c`, TERM=dumb NO_COLOR=1, `HERMES_AGENT=1`; stdout/stderr ≤1 MiB each then dropped (`local-exec-daemon.md:289`); default timeout 30 s; `exit{code,cwd,aborted,abort_reason}`; missing cwd falls back to root with the injected stderr line + `cwd_state`; control `heartbeat` every 3 s), `background_shell_spawn` (detached, log `<root>/terminals/<id>.txt` with Grok's status header), `read` (8 MiB content cap, 1-based offset/limit, negative offset = tail), `ls` (2500-char tree budget per `local-exec-daemon.md:322`, `fd`/`os.scandir`, not ripgrep). `upload`/`download` through the same path jail. `# ponytail: no persistent per-conversation shell state snapshot (env/aliases); cwd is tracked per session only.`
- `hello.capabilities`: `{protocol:1, shell, read, ls, upload_max:104857600, chunk:4194304, max_concurrent:8, backlog:64, local_tools:[], ai_tool_setup:false, permission:"ask|always|never", ceiling}`; re-sent (re-Watch) when permission/capabilities change.
- Local gate (daemon is final authority, port of §5.2): `permission` (default `ask`) and `ceiling`; `ask` requires `authorized_by_approval` + known, non-retired `approval_id` whose `{action,target}` matches; `never` refuses every non-`global` class. Denylist (P3): config `denylist: ["rm:-rf *", …]`, fail-closed when the command cannot be parsed (command substitution/backticks/process substitution/unbalanced quotes) — conservative `shlex` analyser, not tree-sitter; port of §5.4 match forms.
- Path jail: `abs = resolve(root, p)`; reject if outside root, then realpath(root) vs realpath(longest existing ancestor + tail) to defeat symlink escape; atomic write (tmp + rename, preserve mode). **Shell is unjailed and runs as the user** — documented in the enrollment prompt; optional bubblewrap profile deferred (Hermes choice).
- Env scrub for spawned shells: drop `HERMES_*`, the daemon's credential variable, and `ELECTRON_RUN_AS_NODE`-style loader vars; never log request bodies.

**Config (`plugins.entries.machine-relay.settings`)**: `bind: "127.0.0.1:8765"`, `allow_non_loopback: false`, `public_url: ""`, `approval: ask`, `request_ttl_s: 60`, `queue_when_offline: false`, `default_machine: ""`, `credential_ttl_days: 90`, `online_window_s: 20`, `exec_default_timeout_ms: 30000`, `max_reply_bytes: 8388608`.

**Dedup vs Hermes ssh/docker backends:** keep them. `ssh` = host→reachable sshd, session-wide, no per-call approval; `machine-relay` = machine→host, many machines per session, per-frame approval and artifact-bound ids. Neither replaces the other; no shared code beyond documenting when to choose which in the plugin README.

## Host changes
None for P0-P4. Every seam below already exists; signatures and fire-sites were read from the host source:
- `register_tool(name, toolset, schema, handler, check_fn=None, requires_env=None, is_async=False, description="", emoji="", override=False)`: `hermes_cli/plugins.py:483`. Handler returns a JSON string.
- `register_cli_command(name, help, setup_fn, handler_fn=None, description="")`: `plugins.py:684`. Backs `hermes machine enroll|revoke|serve`.
- `register_hook("pre_tool_call", cb)`: `plugins.py:939`. Dispatcher calls `_get_pre_tool_call_directive_details` at `plugins.py:2098` (definition at `:1876`). Approve directive `{"action":"approve","rule_key","revalidate"}`; the `revalidate` field is declared at `plugins.py:1829`.
- Approval gate fire-site: `plugins.py:2044-2061` calls `tools/approval.py:1001` `request_tool_approval(tool_name, reason, rule_key=...)`. Gate failure returns `BLOCKED: plugin approval gate failed` (`plugins.py:2069`).
- Post-approval revalidation runs on the host before execution (`plugins.py:2072-2082`). A non-`True` result yields `BLOCKED: invalid post-approval revalidation` (`plugins.py:2037-2038`). The handler's `revalidate` therefore needs no host change.
- `post_tool_directive` observer: emitted by `_emit_post_tool_directives` (`plugins.py:2111`), called at `plugins.py:2104`. Kwarg `approval_gate` is `"approved"` / `"blocked"` / `None` (`plugins.py:2106`). Used to mint `approval_id`.
- `on_session_finalize`: listed in `VALID_HOOKS` (`plugins.py:149`). Fire-site traced: `hermes_cli/lifecycle.py:63`, called from `hermes_cli/cli_session_mixin.py:438` and `gateway/run_shutdown.py:1062`. Process crashes skip it, so P3 keeps an expiry fallback.
- `register_redaction_patterns(patterns) -> int` (`plugins.py:925`); `on_unload(callback)` (`plugins.py:436`).

Rejected: a `register_terminal_backend` seam (session scope, wrong addressing model); a gateway HTTP-route seam (`serve` as its own process avoids it); `transform_tool_result` changes (results are plain JSON strings).

## Phases
- **P0 store, enroll, listener, `list_machines`.** Accept: `hermes machine enroll` prints a URL once and stores only a hash; a stub daemon's Watch→`connected`; wrong credential or wrong `machine_id` → 401; revoke → `removed`; `list_machines` shows online/offline from `last_seen`.
- **P1 read/ls/upload/download + path jail.** Accept: 9 MiB file read capped with `truncated`; symlink-to-outside refused with the "resolves through a symlink" text; upload of 100 MiB+1 → `file_error`; download of 9 MiB arrives as 3 chunks with monotonic `seq`, `last` only on the final one; empty file → one `{data:"",seq:0,last:true}`.
- **P2 shell + background + cancel + concurrency.** Accept: 9 concurrent `sleep` requests → 8 running + 1 backlogged; 73 → the 73rd gets the busy error; heartbeat frames arrive every 3 s (fake clock); cancel-before-start yields `stream_close`; cancel-after-start kills the process group; exit code, cwd and 1 MiB stream cap observable; 30 s default timeout → `aborted/TIMEOUT`.
- **P3 approvals + permission + denylist.** Accept: with `approval: ask` and no human, the call is blocked by the host gate (fail-closed); approved call carries `approval_id`; daemon with `permission: ask` refuses an exec lacking it; `retire_approval` invalidates it; `never` refuses with the steering text; unparsable command refused fail-closed when a denylist is set.
- **P4 `local_tool` + `discover_ai_tool`.** `local_tool` relays plan-12-guarded computer-use calls to a local `cua-driver` over MCP stdio (serialized per conversation, 2 min request kill, ≤8 MiB reply); `discover_ai_tool` read-only, ≤40 items, strings ≤160 chars. Accept: denied app refused on the *daemon side* too; oversize reply → the "Capture a smaller area" failure.
- **P5 (optional, only if the Hermes host is not user-reachable)** wss relay mode: both sides dial out to a rendezvous, `relay.auth_ok|auth_error` vocabulary from droid. Not planned until needed.

## Tests
- `tests/test_machine_relay.py`: real server on an ephemeral loopback port + real daemon thread + temp `HERMES_HOME`/root; covers wire behaviour above (ack redelivery without double execution, dedupe, caps, chunking, jail, credential binding/revocation/expiry, doorbell latency bound).
- `tests/test_machine_tools.py`: real plugin loader (`HERMES_SOURCE=~/projects/hermes-agent`), asserts tool schemas/routing errors, `pre_tool_call` approve directive and `revalidate` veto, approval-id minting via the real dispatcher with a scripted approval callback, redaction pattern, `approval: never`.
- Failure injection: kill the daemon mid-exec (request surfaces "stopped serving", not hung), drop the server mid-Submit (3×200 ms retry then drop, request re-times out), clock jump.

## Risks & open questions
- Shell is full user authority; approval is the only control until a sandbox profile ships. A compromised Hermes host owns every enrolled machine — blast radius equals the credential set; hence per-frame approval, expiry, revoke, and no standing "always" by default.
- Handler's `tool_call_id` availability is unverified; approval-id minting keys on canonical args within 5 min if absent. Duplicate identical commands inside that window share one approval (same as Grok's `{action,target}` match).
- Header-vs-body credential and SSE-over-POST differ from Grok (Connect RPC); behaviour is identical but no wire compatibility with Grok clients is claimed.
- Doorbell by DB scan adds ≤250 ms latency; acceptable for tool-call granularity.
- Linux/macOS/Windows shell differences (`bash` assumed; Windows daemon needs `pwsh` handlers) — P1-P3 target Linux+macOS only.
- Decision needed from owner: where `hermes machine serve` is supervised (gateway unit vs standalone).
- `on_session_finalize` fire-site traced (`hermes_cli/lifecycle.py:63`; callers `cli_session_mixin.py:438`, `gateway/run_shutdown.py:1062`). Process crashes skip it, so P3 adds an expiry fallback (`approvals.retired_ms` by age) regardless.
- `revalidate` is only a veto on the host's final args; a TOCTOU window remains between `revalidate` and the daemon's own file/command execution. Accepted because the daemon gate (`permission`, `denylist`) is the final authority.

## Non-goals
`messages_op`/iMessage, Contacts, phone-as-machine, VNC/box lifecycle, egress tunnel, hosted multi-tenant relay, persistent shell state snapshots, tree-sitter parsing, replacing Hermes' ssh/docker backends, automatic machine selection, any standing grant without explicit user consent.
